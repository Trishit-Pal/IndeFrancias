# FrenchPath Stage 2 — 13 interface languages

> **For agentic workers:** executed with superpowers:subagent-driven-development. Implementers get a
> hand-written brief per task from the controller; do not read this whole file unless told to.
> Approved by the owner on 2026-11-11.

## Context

Steps 1 and 2 of the launch-check plan are done: PR #18 (critical/high review findings) and PR #19
(medium findings + audit gate) are merged into `main` (`981d096`). This is **Stage 2: languages**,
on branch `feat/i18n-13-locales`.

Three owner decisions (2026-11-11):

1. **Which three languages:** Malayalam (`ml`), Odia (`or`), Assamese (`as`). All left-to-right.
2. **Translation depth:** AI-draft real interface text at build time for all 10 Indic locales
   (`bn ta te kn mr gu pa` + `ml or as`), finish Hinglish, keep every drafted locale labelled beta,
   and hand Stage 3 (human proofread kit) drafts to correct.
3. **Lesson glosses:** the three also become native-language choices, with AI-drafted glosses
   (712 gloss maps each, 2,136 entries); their gloss fallback is English, not Hindi.

**Where things stand (measured at `981d096`):**
- 10 locales, 452 message keys (+ `$schema`). Strings still identical to English: `hi` 3,
  `hinglish` 266, each of the seven beta locales 423.
- The list of languages is hard-coded in more than ten places (see "Facts from the code map").
- 11 backup/sync error messages are English-only strings thrown from `pwa/backup.ts`,
  `sync/mergeFile.ts`, `sync/crypto.ts` and shown raw in every locale.

**Outcome:** 13 selectable interface languages, each with real (draft, beta-labelled) text;
Malayalam, Odia and Assamese learners get glosses in their own language; one registry so the next
language is a one-file change; no English placeholders left to track by hand.

## Global Constraints

- No IndexedDB version change, no backup-format change, no new dependency, no network call, no CSP
  change. No SPEC §3 invariant or §7 ADR edit.
- Translation is done by the implementer subagents themselves, writing the message and gloss files
  directly: no API key, no new script that calls a model.
- Every drafted locale stays labelled "(beta)": a machine check is not a native proofread.
- Copy: polite second person; warm, never guilt or urgency (SPEC invariant 6). Keep every
  `{placeholder}`; keep French words and examples in French; keep `FrenchPath`, `XP`,
  `DELF`/`DALF`, `FSRS`, Latin digits.
- Message files keep the key order and tab indentation of `en.json`. Run `i18n:compile` after
  message edits (`src/lib/paraglide` is generated and git-ignored).
- Preserve every existing `data-testid`, aria attribute and message key.
- Every task: `npm run check && npm run lint && npm run test:unit -- --run` green before its
  commit; e2e files named in the brief, only on `PORT=4176`, never two runs at once.
- One commit per item, conventional message, empty body, no AI attribution.
- Test baseline before this branch: 577 unit (57 files) + 106 e2e (103 passed, 3 skipped).

## Tasks

### Task 1 — Language registry (refactor, no behaviour change)
New pure module `frenchpath/src/lib/i18n/languages.ts` (no `$lib` alias, no Paraglide import, so
the `tsx` scripts can import it too). It owns:
- `UI_LANGUAGES`, `NATIVE_LANGUAGES` (const arrays; `UiLanguage` / `NativeLanguage` derive from them),
- per-language data: own-script label, `beta` flag, `htmlLang` (`hinglish` → `en`),
  native → UI default, gloss fallback chain, expected Unicode script range.

Everything else reads from it; existing export names stay so the files importing
`NativeLanguage` / `UiLanguage` do not change:
- `db/schema.ts` re-exports the two types; `profile/types.ts` re-exports `NATIVE_LANGUAGES`,
  `NATIVE_TO_UI`, `NATIVE_LANGUAGE_LABELS`, `BETA_LOCALES` (and keeps `uiLanguageLabel`, which needs `m`);
- `backupSchema.ts` and `content/schema.ts` build their `z.enum` from the arrays;
- `settings/+page.svelte` list, `+layout.svelte` `html lang`, `content/gloss.ts` fallback chain;
- `scripts/lib/regionalGloss.ts` (`NATIVE_LANGS`, `SCRIPT_RANGES`) and the gloss scripts.

Tests first (`languages.spec.ts`): registry equals `project.inlang/settings.json` locales; equals
the set of `messages/*.json` files; every non-Latin locale has an `html[lang='x']` rule in
`theme/tokens.css`. `localeCoverage.spec.ts` loads locales with `import.meta.glob` instead of ten
imports. All existing tests pass unchanged.

### Task 2 — Add `ml`, `or`, `as` as interface languages
- **Spike first:** add the three to `project.inlang/settings.json`, run `i18n:compile` + `check`.
  `or` and `as` are also JS/TS keywords in some positions; if the generated code does not compile,
  STOP and report (do not rename the locales silently).
- Registry entries: labels മലയാളം, ଓଡ଼ିଆ, অসমীয়া; `beta: true`; interface languages only for now.
- `messages/{ml,or,as}.json` seeded from `en.json` (placeholders; drafted in Task 5).
- `theme/tokens.css`: `html[lang='ml']` → Noto Sans Malayalam, `or` → Noto Sans Oriya,
  `as` → Noto Sans Bengali (system fonts only; no bundled Indic fonts), and the three added to the
  `:is([lang=…])` line-height list.
- Tests: settings picker lists 13; "(beta)" label for the three; registry spec red then green.

### Task 3 — Translatable backup and sync errors
`backup.ts`, `mergeFile.ts`, `crypto.ts` throw 11 English sentences that the Settings page shows
raw. Give them a typed code (one small error class with a `code` union, in the style of the
existing `WrongPassphraseError` / `FutureDatedSyncError`), and map code → message key in one
function next to `syncErrorMessage` in `settings/+page.svelte`. Messages keep their meaning.
New keys in all 13 files: real text in `en`, `hi`, `hinglish`; the rest are drafted in Task 5.
Review seat: `pwa-data-reviewer` (error paths only; no write logic changes).

### Task 4 — Finish Hinglish
Translate the strings still identical to English (Latin-script Hindi-English mix, matching the
existing ones). Test first: the "no English placeholders" rule that `hi` has is extended to
`hinglish`, with an allowlist for strings that are legitimately the same.

### Task 5 — Draft interface text for the 10 Indic locales
Five dispatches, two related locales each, model `opus`:
`bn`+`as` · `mr`+`gu` · `pa`+`or` · `ta`+`ml` · `te`+`kn`.
One term table per locale (Review, Lesson, Streak, Backup, Sync, …) at the top of the report,
applied consistently. Test first: a `DRAFTED_LOCALES` list in the coverage spec — adding a locale
fails (N strings identical to English, or prose without the locale's script), filling it passes.
Review per dispatch (`sonnet`): keys, placeholders, script, no leftover English, and a
back-translation of 40 sampled strings per locale.

### Task 6 — Gloss draft tooling
New `frenchpath/scripts/gloss-drafts.ts` (pure merge function + thin CLI, unit-tested):
- `--export` writes a worklist per language: one entry per gloss map (card or example) with the
  French text and the English gloss, keyed `unitId/cardId[/example]`;
- `--apply` merges `scripts/gloss-drafts/<lang>.json` into `src/content/packs/**` under
  `glosses.<lang>`, and fails on a missing key or a value without the expected script.
The draft files stay in the repo (they are the flat files a proofreader gets in Stage 3).

### Task 7 — Draft glosses and make the three native-language choices
- Three dispatches (`opus`), one per language, each filling 712 entries from its worklist.
- Apply; then, in the same task, add `ml`, `or`, `as` to `NATIVE_LANGUAGES` (before `en`),
  the native → UI defaults, and gloss fallback `['en']` for the three (existing languages keep
  `hi` → `en`). This order keeps `content:validate` and `content:proofread:launch` green at every commit.
- `content/schema.ts`: `titleByLang` / `bodyByLang` become `z.partialRecord` like `hintByLang`.
- Tests: `gloss.spec.ts` — a Malayalam learner gets the Malayalam gloss, and English (not Hindi)
  when one is missing; `backupSchema.spec.ts` — a backup with `nativeLanguage: 'ml'` restores.

### Task 8 — End-to-end proof in the new languages
- `e2e/i18n-locales.e2e.ts` (mobile project): for each of the 13 locales open home, review,
  progress, settings; assert no horizontal overflow, no console error, `html lang` correct.
- Onboarding in Malayalam: `native-lang-ml` → interface switches, first lesson shows a Malayalam gloss.
- Fix what the overflow test finds with the smallest CSS change (or a shorter draft string).
- Add `dark/ml` to the axe matrix in `e2e/accessibility.e2e.ts`.

### Task 9 — Docs, size gate, spec sync
- `docs/i18n-pending.md`: replace the line-by-line list with a short status page and the new rule
  for adding a key (draft it in all 13 locales; the coverage spec enforces it).
- Beta now means "draft translation, not yet proofread by a native speaker".
- Size gate: rebuild, compare with the Task 0 baseline. **If total precache grows by more than
  500 KB or any route's JS (gzip) by more than 30 %, stop and ask the owner.**
- Spec sync: CAP-I18N, CAP-GLOSS, CAP-ONB, CAP-BACKUP/CAP-SYNC, §5 baseline, §11 row; the docs
  that state "10 locales" (listed below).

### Finish
Controller's full gate, whole-branch review on the most capable model, at most one fix wave with a
scoped re-review, rulings and deferred minors listed for the owner. Ask before pushing or opening the PR.

## Facts from the code map (2026-11-11)

Found after the plan was approved; they refine the tasks above and do not change the decisions.

- **`uiLanguageLabel` looks labels up in `NATIVE_LANGUAGE_LABELS`**, so today every interface
  locale except `hinglish` must also be a native language. The registry (Task 1) keeps one label
  per language code, so Task 2 can add interface-only locales.
- **`glossesSchema` (`content/schema.ts:43-53`) is a strict object with all 9 keys required**,
  not a record. A new native language makes every gloss map invalid until filled — which is why
  Task 7 applies the drafts and extends the list in one commit.
- `theme/tokens.css` has **two** language lists: the per-language font blocks (`:201-228`) and an
  `html:is([lang=…])` list (`:234-243`) for line height / letter-spacing.
- `vite.config.ts:33-39` uses the Paraglide strategy `['localStorage', 'preferredLanguage',
  'baseLocale']`: a browser that prefers a newly added language gets that interface before onboarding.
- `scripts/proofread-report.ts:18-28` `hasIndicInFrenchText` lists the ranges 0900, 0980, 0A00,
  0B00, 0C00, 0D00, 0A80 — it misses Tamil (0B80) and Kannada (0C80). Fix by reading the registry's
  ranges (Task 6).
- **`scripts/seed-ui-locales.ts` rewrites every locale in its `OVERRIDES` from `en.json`** and
  would wipe drafted translations. Delete it in Task 5 (its job is done).
- `scripts/seed-regional-glosses.ts` + `scripts/lib/regionalGloss.ts:69-89` rebuild `glosses{}`;
  Task 7 must make sure a re-run cannot drop the `ml`/`or`/`as` drafts.
- Existing tests that name languages: `i18n/localeCoverage.spec.ts`, `content/gloss.spec.ts:10-40`
  (fixture needs the new keys), `pwa/backupSchema.spec.ts:91-106`, `pwa/backup.spec.ts:386` (uses
  `'ur'` as the unknown language — still unknown), `e2e/app.e2e.ts:182-189` (the language-select
  test; SPEC's CAP-I18N row wrongly points at `e2e/settings.e2e.ts`), `e2e/accessibility.e2e.ts:118`.
- Docs that state the count or the codes: `docs/spec/SPEC.md:12,95,112`, `frenchpath/README.md:26,129`,
  `PRODUCT.md:56`, `docs/architecture-map.md:39`, `docs/product/prd.md:15,51`,
  `docs/product/gtm-launch.md:24,37`, `docs/testing.md:403`,
